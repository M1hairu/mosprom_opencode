# Проверки плана (`POST /api/validate`, #30)

Вход — PlanDocument v1 pochta (`api.contracts.PlanDocument`). Выход — список находок
`Finding`: код, важность (`error` или `warning`), текст, ссылки на объекты. Форма находки
совпадает с `Finding` в `web/src/planner/model.ts`.

Проверки идут в таком порядке:

1. `pochta.py` — 22 кода pochta `validatePlan` (commit c9991cc), те же тексты и порядок.
2. `safety.py` — лазер и пожар: G5 (TRAP-4), D-001, G15.
3. `evacuation.py` — эвакуация: G16, G17 (СП 1.13130.2020).

Контур с самопересечением (`POLYGON_UNUSABLE`) останавливает проверку после шага 1.

## Ключи

Факты ЛАССАРД, для которых в формате нет поля, лежат в `attributes` и `extensions`.
Если у объекта нет атрибута, проверка берёт `default` атрибута его типа в каталоге.

| Где | Ключ | Значение | Правило |
|---|---|---|---|
| объект | `beam` | `"open"` — открытый луч класса 4; `"closed"` — закрытый луч; ключа нет — у объекта нет луча | G5 |
| объект | `live` | `true` — работает (D-001 это запрещает); `false` — без питания; не указан — неизвестно: у объекта с `beam` (открытый или закрытый) это включено, у остальных (мебель, колонны) — выключено | G5, D-001, G15 |
| объект | `category` | процесс (для текста находки). Нет ключа — `category` типа | D-001 |
| зона | `interlock` | `true` — открытая дверь выключает лазер; зона считается кабиной, только если стены замыкают её контур | G5 |
| зона | `fireBarrier` | предел преграды, например `"EIW 45"`; отсек Ф5.1 | G15, G16 |
| план | `extensions.safety.capacity` | людей в зале одновременно. Нет ключа — порог для 50 человек и более | G17 |

## Коды правил #30

| Код | Важность | Что значит |
|---|---|---|
| `OPEN_BEAM_OUTSIDE_INTERLOCK` | error | Открытый луч не в замкнутой стенами зоне с `interlock`, и `live` не `false` (`live` не указан — тоже находка) |
| `LIVE_PROCESS_FORBIDDEN` | error | Любой объект с `live: true`; объект с лучом (`beam` открытый или закрытый), у которого `live` не указан (= включено); открытый луч вне кабины даёт `OPEN_BEAM_OUTSIDE_INTERLOCK`, не эту находку. Одна находка на объект. В шоуруме нет живого процесса с лучом (D-001) |
| `LASER_ZONE_NO_FIRE_BARRIER` | error | Станок с `live: true` вне зоны с `fireBarrier`, или стены не замыкают эту зону |
| `EXITS_TOO_FEW` | error | Нет выхода; один выход при 50 людях и более или при пути больше 25 м |
| `EXIT_TOO_NARROW` | error | Выход уже 0,8 м, при 50 людях и более — уже 1,2 м |
| `EXIT_TOO_FAR` | error | Путь до ближайшего выхода больше 30 м (Ф2.2, табл. 5) |
| `PASSAGE_TOO_NARROW` | error | Часть зала связана с выходом только проходом уже 1,0 м (больше 50 людей — 1,2 м) |
| `EXIT_UNREACHABLE` | error | Часть зала не связана с выходом |
| `EVACUATION_NOT_CHECKED` | warning | Помещение больше сетки 250 000 клеток: путь не проверен |

Путь меряется по сетке 0,25 м в обход стен и физических объектов на полу. Пол отсека с
`fireBarrier` вырезан из сетки зала: путь зала не начинается в отсеке и не идёт через него.
Выход в стене отсека всё равно входит в число выходов (`EXITS_TOO_FEW`). Нормы взяты из вторичного источника: сверить по
официальному тексту (`concept/05-safety.md`, 4.2).

## Отличие от pochta

Объект слоя `l_building` — элемент здания (D-014). Флаг `locked` значит только «нельзя
двигать» и здание не отмечает. Пример — колонна в наружной стене. Он остаётся препятствием и сталкивается с
подвижными объектами. Проверки размещения, стен, проёмов, потолка и зон его пропускают.
Две колонны друг с другом не сталкиваются.

## Ограничения

- Размер плана: объектов ≤ 300, стен ≤ 200, проёмов ≤ 200, зон ≤ 100, слоёв ≤ 50, типов ≤ 200,
  правил ≤ 50. Больше — ответ 422. Плотный план на этих пределах проверяется за ≈ 2 с.
- Одна вместимость на весь план. Комната внутри зала (переговорная) берёт тот же порог.
- Ширина прохода — зазор между двумя препятствиями, а не ширина пути по всей длине.

## Совпадение с pochta

`backend/tests/test_validation_parity.py` сверяет `pochta.py` с выводом pochta на планах
`backend/tests/fixtures/parity/`. Ожидание `expected.json` получают так (pochta на c9991cc):

```
cd <pochta> && POCHTA=$PWD node_modules/.bin/tsx \
  <repo>/backend/tests/fixtures/parity/pochta_run.mts \
  $(ls <repo>/backend/tests/fixtures/parity/*.json | grep -v expected.json) \
  > <repo>/backend/tests/fixtures/parity/expected.json
```

## eval (а)

`eval/cases-norms.json` — планы зала 219 с известными нарушениями и чистые планы.
`make eval` печатает долю пойманных и долю ложных (`metric()` в `backend/src/api/checks.py`).
Holdout в `metric()` не передаётся: на `eval-final` метрика (а) не печатается.
